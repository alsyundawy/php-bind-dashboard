# BIND9 Integration

## How it works

PHP-Bind-Dashboard stores **metadata** (zone name, type, serial, notes, permissions) in SQLite.

The actual DNS data lives in standard BIND zone files under the configured `zones_dir`.

When you create a zone:

1. A zone file `db.example.com` is generated with a basic SOA + NS records.
2. An entry is appended to `named.conf.local` (if writable).
3. Metadata is saved in the database.

When viewing a zone, the zone file is parsed (simple parser supporting common record types).

## Required BIND configuration

Make sure `named.conf` includes your local zones:

```
include "/etc/bind/named.conf.local";
```

Example zone entry generated by the dashboard:

```
zone "example.com" {
    type master;
    file "/etc/bind/zones/db.example.com";
};
```

## Permissions

The PHP-FPM / web server user must be able to:

- Write to the zones directory
- Optionally write to `named.conf.local`
- Execute `rndc` (if you want automatic reload)

Example:

```bash
usermod -aG bind www-data
chown root:bind /etc/bind/zones
chmod 775 /etc/bind/zones
```

## Reload

If `rndc` is available and executable, the application can call `rndc reload <zone>` after changes.
Otherwise you must reload manually:

```bash
rndc reload
# or
systemctl reload bind9
```

## Limitations (v1.0)

- Zone file parser is intentionally simple (no full `$GENERATE`, complex multi-line, etc.)
- Record editing UI is read-only in the current release (edit zone files directly or extend the controller)
- Slave / forward zones are registered but AXFR/notify logic is left to BIND itself
